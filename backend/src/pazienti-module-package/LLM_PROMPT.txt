POTENTIAL ISSUES AND SOLUTIONS:

Issue: "Cannot resolve decorator signature"
Solution: Run `npm install` to ensure all dependencies installed

Issue: "JSON type not defined in GraphQL"
Solution: Add `import { GraphQLJSONObject } from 'graphql-type-json'` and register in resolvers

Issue: "Table patients already exists"
Solution:
- Option A: Drop old table (if safe): `DROP TABLE patients CASCADE;`
- Option B: Migrate data from old table to new
- Option C: Use different table name (rename in entity)

Issue: "Circular dependency between Appointment and Paziente"
Solution: Already handled with lazy loading - ensure both entities use `lazy: true`

Issue: "Service method not found"
Solution: Check that pazienti.service.ts copied correctly and all imports resolved

KEY POINTS TO REMEMBER:

1. **Naming Convention**: This module uses ENGLISH naming (name, surname, phone) not Italian (nome, cognome, telefono)

2. **Table Name**: Creates table `patients` not `pazienti`

3. **GraphQL Code-First**: Uses decorators (@ObjectType, @InputType, @Field) not schema-first

4. **JSONB Fields**: Requires graphql-type-json package for proper serialization

5. **Lazy Loading**: All relations use lazy loading to avoid circular dependencies

6. **GDPR Compliance**: Includes built-in anonymization and consent management - USE these methods, don't delete records directly

7. **Workflow States**: Patient records follow state machine (BOZZA → PARZIALE → COMPLETA → DA_VERIFICARE)
